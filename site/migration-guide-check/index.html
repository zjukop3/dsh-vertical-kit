检查规则

规则判定
title-missing没有 `# 标题`，也没有 frontmatter 的 title: → error
from-to-missing既没有版本跨度（从 0.1.0 到 0.2.0），标题里也没有迁移目标（Migrating to v5）→ error；只有版本号不算
breaking-missing没有破坏性变更段、也没有至少三节讲变更的小节 → error
steps-missing没有编号步骤 → warn（--require-steps 时 error）；散文与项目符号都不算
steps-thin步骤少于下限（默认 3，可调）→ warn
verify-missing没有验证方式 → warn，仅流程型指南（有编号步骤）
rollback-missing没有回滚方案 → warn，仅流程型指南（--require-rollback 时 error）
backup-missing没有备份提示 → warn，仅流程型指南

用法

npx migration-guide-check guide.md --json
npx migration-guide-check guide.md --min-steps 5 --require-steps --require-rollback
npx migration-guide-check guide.md --check-recovery

真实输入输出

输入
# 升级说明

我们改了参数名，升级后注意一下。

$ migration-guide-check migration-sample.md
error from-to-missing 第0行 没有版本跨度（认得：从 0.1.0 到 0.2.0、0.1.7 → 0.2.0、from v1 to v2）——「升级到 0.2.0」是发布说明，不是迁移指南
error breaking-missing 第0行 没有可逐条对照的变更清单（认得：## 破坏性变更、## Breaking changes，或至少三节讲变更的小节）——散文里提一句「这次不兼容」不是清单
warn steps-missing 第0行 没有编号步骤（认得：1. … 2. …）——有步骤的指南能照着做，没有的只能照着读
fail: span unstated, 0 steps, 2 errors, 1 warnings

出口码：1。输出为真实 CLI 运行的逐字结果，由测试与工具保持同步。

出口码：0 干净、1 有发现、2 用法或读文件错误。--json 输出机器可读结果。DSH 内同样的函数在 POST /migration-guide-check/api（{"text":"…"} 或 {"path":"…"}），面板与 CI 调同一实现。

这是清单，不是专业人士。合同检查不是法律意见，发票检查不判税务合规，listing 检查不判商业价值。每条发现都是文本里可判定的结构缺陷，带行号。
实测两份真实指南（Vite docs/guide/migration.md 与 TanStack Query 的 Migrating to v5）：0 error、1 warn（steps-missing）。恢复类三问（验证/回滚/备份）只对流程型指南（有编号步骤）查——不加这个条件，三条在 100% 的真实指南上都会开火。只管指南的形状，不管内容对不对：步骤本身错、跨度漏了一个版本，都验不出来——那要在临时 profile 里真跑一遍。项目符号刻意不算步骤：迁移是有序动作，`-` 列表不承诺顺序。 · dsh-vertical-kit · 通用检查（哈希/引用/结构/表格/数字）在 dsh-verify-kit
