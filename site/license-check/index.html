检查规则

规则判定
empty文件没有内容 → error
unrecognized正文不是任何已知许可证条文 → error
title-body-mismatch标题写 MIT、正文是 Apache → error
declared-mismatch--expected 声明值与正文不一致 → error
copyright-missing没有 Copyright 行 → error
copyright-year-missing / copyright-holder-missing版权行缺年份或缺人名 → error
copyright-year-future年份在未来 → error
copyright-year-stale静态过去年份（一次性发布正常）→ warn
placeholder-left<year>、[fullname]、{{…}} 没填 → error

用法

npx license-check LICENSE --json
npx license-check LICENSE --expected MIT

真实输入输出

输入
MIT License

Copyright (c) 2026

Permission is hereby granted, free of charge, to any person obtaining a copy.

THE SOFTWARE IS PROVIDED "AS IS", WITHOUT WARRANTY OF ANY KIND.
$ license-check LICENSE.sample
error copyright-holder-missing 第3行 第 3 行 Copyright 没有版权人名称
fail: detected=MIT, 1 errors, 0 warnings

出口码：1。输出为真实 CLI 运行的逐字结果，由测试与工具保持同步。

出口码：0 干净、1 有发现、2 用法或读文件错误。--json 输出机器可读结果。DSH 内同样的函数在 POST /license-check/api（{"text":"…"} 或 {"path":"…"}），面板与 CI 调同一实现。

这是清单，不是专业人士。合同检查不是法律意见，发票检查不判税务合规，listing 检查不判商业价值。每条发现都是文本里可判定的结构缺陷，带行号。
认得 12 种许可证正文（MIT/Apache-2.0/BSD-2/BSD-3/ISC/GPL-2.0/GPL-3.0/LGPL-3.0/AGPL-3.0/MPL-2.0/Unlicense/CC0-1.0），按正文短语匹配而非标题——所以「标题 MIT 正文 GPL」会被抓。只验文件形态与身份，不验法律效力：许可是否合适、依赖是否兼容、版权人是否正确的法律主体，都不是机器能担保的部分。 · dsh-vertical-kit · 通用检查（哈希/引用/结构/表格/数字）在 dsh-verify-kit
