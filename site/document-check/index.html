DSH VERTICAL KIT · AGENT TOOL

一条工具，32 个检查

这些检查原本只有 HTTP 端点：人得记得去 POST，agent 没有理由调用它。工具的差别不是包装，是位置——它出现在模型能自己看见、自己决定调用的那一层，于是「交付前先查一遍」这件事才可能真的发生。

为什么是一条，不是 32 条

32 条工具定义会挤占上下文，而模型在前十分钟里分不清 adr_check 与 spec_doc_check 该用哪个。一条工具加一个 check 参数：genre 的选择留在模型已经知道的地方——它刚写完的那份文档里。

装

dsh plugin --profile <profile> add dsh-document-check

--profile 是必填项。工具在下一个会话出现在 agent 的工具集里；在那之前「确认装好了」只证明包装上了，不证明工具注册了。

调用长什么样

document_check({ check: 'adr-check', text })
→ ok: false, 3 error(s), 1 warning(s)
  error status-missing line 0: 没有状态（认得：状态：已接受、Status: Accepted、…）
  error decision-missing line 0: 没有决定段——ADR 的核心就是那一句「我们选了 X」

每次最多回 25 条并显式标注截断：把两百条灌进上下文的检查器会被关掉，而前 25 条本来就是该先修的。

能查哪些

check检查清单它决定什么
agreement-check合同结构检查清单这份合同在结构上是否可审
invoice-check发票字段检查清单发票上能从文本判定的算术与格式是否成立
listing-check电商商品信息检查清单商品导出表是否达到可上架的结构卫生
meeting-notes-check会议纪要检查清单这份纪要是否交代了谁在何时 carries 什么
resume-check简历检查清单这份简历在书记层面是否可读、可达、时间自洽
release-notes-check发布说明检查清单这份发布说明是否交代了哪个版本、何时、什么会坏、怎么迁移
weekly-report-check周报检查清单这份周报是否交代了做完了什么、接下来做什么、什么会卡住、进展是否可检验
bug-report-check缺陷报告检查清单这份 bug 报告是否交代了在哪发生、怎么触发、差在哪
api-doc-check接口文档检查清单这份接口文档是否交代了怎么调、怎么证明身份、失败长什么样
test-report-check测试报告检查清单这份测试报告的算术是否自洽、环境是否可复跑、失败是否有去处
commit-msg-check提交信息检查清单这条提交信息是否可被工具解析、在 log 里可读
dockerfile-checkDockerfile 检查清单这个 Dockerfile 是否把可复现与最小权限写进了文件本身
env-example-check环境变量示例检查清单这份示例文件是否只含占位符、键不重复、有用途说明
license-check许可证检查清单这个 LICENSE 文件是否说了它看起来在说的那件事
incident-report-check事故复盘检查清单这份复盘是否给出了时间线、影响、根因与有人负责的后续
ops-runbook-check运维手册检查清单这份手册是否给了读者前置、步骤、退路、确认方式，以及危险命令旁的警告
pr-description-checkPR 描述检查清单这条 PR 描述是否给了 reviewer 能动手的 what / why / how-verified
spec-doc-check需求文档检查清单这份方案是否让 reviewer 能精确地反对它
adr-check架构决策记录检查清单这份决策记录是否让后来人能重新评估它
onboarding-check上手指南检查清单这份上手文档是否让一个新人今天就能开始
handover-check交接单检查清单这份交接单能不能让接手人在没有人讲解的情况下接住工作与凭证
expense-claim-check报销单检查清单这张报销单能不能在不手工加总的情况下被核对与付款
security-advisory-check安全公告检查清单这份安全公告能否让人判断「我会不会被影响、现在该做什么」
migration-guide-check升级迁移指南检查清单这份迁移指南能否让人在没人可问的情况下把升级做完
privacy-notice-check隐私声明检查清单这份声明能否回答读者「我的数据去哪、留多久、我能要求什么」
contributing-check开源贡献指南检查清单这份贡献指南能否让一个陌生人自己把第一个 PR 交上来
perf-report-check性能报告检查清单这份性能报告能否被别人读懂并复跑
plugin-entry-check插件目录条目检查清单这份目录条目会不会被目录的 CI 打回，以及打回在哪一行

另加 citelint、numberlint、outline-lint、tablelint 四个通用检查（来自 dsh-verify-kit）。hashcheck 不在里面：它算摘要，不读文档。

边界

  • 只判结构。它说这份 ADR 有「后果」段，从不说这个后果可以接受。
  • 不猜文体。拿简历去过 invoice-check 是被允许且没用的；工具相信调用方。
  • 清单是生成的。新加一个检查却没重跑生成器，工具会说自己有 32 个而仓库里有更多——测试就卡这一条。
