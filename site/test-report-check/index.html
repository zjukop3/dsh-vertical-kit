检查规则

规则判定
counts-missing没有任何用例计数 → error
sum-mismatch通过+失败+跳过 ≠ 总计 → error，报出算式与两边数字
env-missing没有测试环境 → error
failure-detail-missing报了失败但没有失败详情段 → error
total-missing有分项没总数 → warn
counts-partial有总数没分项 → warn

用法

npx test-report-check report.md --json

真实输入输出

输入
# 测试报告

今天跑了测试，大部分都过了。
$ test-report-check test-sample.md
error counts-missing 第0行 全文没有任何用例计数（认得：通过 12、失败 3、跳过 1、总计 15）——测试报告没有计数就不是报告
error env-missing 第0行 没有测试环境（认得：## 测试环境、环境：…、OS：…、Node：v…）——不写环境的结果无法复跑
fail: {}, 2 errors, 0 warnings

出口码：1。输出为真实 CLI 运行的逐字结果，由测试与工具保持同步。

出口码：0 干净、1 有发现、2 用法或读文件错误。--json 输出机器可读结果。DSH 内同样的函数在 POST /test-report-check/api（{"text":"…"} 或 {"path":"…"}），面板与 CI 调同一实现。

这是清单，不是专业人士。合同检查不是法律意见，发票检查不判税务合规，listing 检查不判商业价值。每条发现都是文本里可判定的结构缺陷，带行号。
只验书记层面，不验测试质量：它验证数字是否对得上、环境是否写明、失败是否有去处；用例是否真的覆盖了什么，靠覆盖率和评审。 · dsh-vertical-kit · 通用检查（哈希/引用/结构/表格/数字）在 dsh-verify-kit
