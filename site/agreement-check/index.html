合同结构检查清单

它决定一件事：这份合同在结构上是否可审。

dsh-agreement-checkdsh-invoice-checkdsh-listing-checkGitHub 源码npm

检查规则

规则判定
party-a / party-b没有「甲方：/乙方：」行，或名称为空 → error，报行号
date全文无日期 → error；有日期但没有「签订/签署日期」字样 → warn
amount-uppercase有数字金额但全文没有大写金额 → error
amount-mismatch大写金额与所有数字金额都对不上 → error，报两边的值
amount-ambiguous出现多个大写金额 → warn（自动比对仅在恰好一个时进行）
signature没有「甲方（盖章）/乙方（盖章）」式签署栏 → error
dispute没有争议解决条款（仲裁/诉讼/管辖）→ error
breach没有违约责任条款 → error
term没有期限条款 → warn

用法

npx agreement-check contract.md --json
npx agreement-check contract.md --warnings-fail

出口码：0 干净、1 有发现、2 用法或读文件错误。--json 输出机器可读结果。DSH 内同样的函数在 POST /agreement-check/api（{"text":"…"} 或 {"path":"…"}），面板与 CI 调同一实现。

这是清单，不是专业人士。合同检查不是法律意见，发票检查不判税务合规，listing 检查不判商业价值。每条发现都是文本里可判定的结构缺陷，带行号。
大写金额解析器按 GB 习惯读 壹贰叁…拾佰仟万亿元角分整，支持「拾万元整」的 leading 拾 和 角分小数；解析不了的串返回 null 并计入歧义，不会编一个数出来。 · dsh-vertical-kit · 通用检查（哈希/引用/结构/表格/数字）在 dsh-verify-kit
