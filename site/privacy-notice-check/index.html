隐私声明检查清单

检查规则

规则判定
title-missing没有 `# 标题`，也没有 frontmatter 的 title: → error
data-missing没有说明收集什么 → error；认得 information we collect、personal data that we process；「不收集任何数据」也是答案
purpose-missing没有用途段或带标签的一行 → error
retention-missing没有保留期限 → error；「不保留」也是答案
sharing-missing没有共享段 → error；认得 共享、第三方、disclose、subprocessor；散文里提到「第三方」不算声明
contact-missing没有联系段、标签行或邮箱 → error
effective-date-missing没有生效或更新日期 → warn
rights-missing没有权利说明（## 你的权利、你有权访问/删除…）→ warn（--require-rights 时 error）

用法

npx dsh-privacy-notice-check notice.md --json
npx dsh-privacy-notice-check notice.md --require-rights --warnings-fail

真实输入输出

输入
# 隐私声明

我们很重视你的隐私，会尽力保护你的信息。

$ privacy-notice-check privacy-sample.md
error data-missing 第0行 没有说明收集什么（认得：## 我们收集的信息、收集的信息：…，或不收集）——这是读者第一个要问的
error purpose-missing 第0行 没有说明用途（认得：## 使用目的、用途：…、## How we use it）——「为了提供服务」和「什么都能干」是两种声明
error retention-missing 第0行 没有保留期限（认得：## 保留期限、保留时间：30 天，或不保留）——没有期限，「注销账号」就不等于数据会消失
error sharing-missing 第0行 没有第三方共享说明（认得：## 共享、## 第三方、共享：…）——散文里提到「第三方」不算声明，读者指不出哪一句是承诺
error contact-missing 第0行 没有联系方式（认得：## 联系我们、联系邮箱：…、privacy@example.com）——没有渠道，行使权利就是空话
warn effective-date-missing 第0行 没有生效或更新日期（认得：生效日期：2026-11-01、last updated）——不知道版本的声明，无法判断哪一版约束我
warn rights-missing 第0行 没有用户权利说明（认得：## 你的权利、你有权访问/删除…、Your rights）——只说收集不说权利，读者只能猜自己能要求什么
fail: 5 errors, 2 warnings

出口码：1。输出为真实 CLI 运行的逐字结果，由测试与工具保持同步。

出口码：0 干净、1 有发现、2 用法或读文件错误。--json 输出机器可读结果。DSH 内同样的函数在 POST /privacy-notice-check/api（{"text":"…"} 或 {"path":"…"}），面板与 CI 调同一实现。

这是清单，不是专业人士。合同检查不是法律意见，发票检查不判税务合规，listing 检查不判商业价值。每条发现都是文本里可判定的结构缺陷，带行号。
实测 GitHub 自己的两份政策（General Privacy Statement、Candidate Privacy Notice）零发现；cookies 政策报 5 条，那是正确的——它不是隐私声明。frontmatter 的 title: 也算标题。只验声明有没有回答问题，不判断它在哪个法域合法：不分 GDPR 与 PIPL，不核对声明的保留期和代码实际行为是否一致，也无法判断「我们不共享」是真是假。声明写「不收集」并且说清楚了，就按答案算——在否定式答案之上再要求一节，只会教作者写废话。 · dsh-vertical-kit · 通用检查（哈希/引用/结构/表格/数字）在 dsh-verify-kit
