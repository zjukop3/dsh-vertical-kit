周报检查清单

它决定一件事：这份周报是否交代了做完了什么、接下来做什么、什么会卡住、进展是否可检验。

检查规则

规则判定
done-missing没有「本周完成」段或自标识行（已完成…、已上线…）→ error
plan-missing没有「下周计划」段或自标识行（计划…、下周…）→ error
risks-missing没有风险/阻塞段 → warn（信息里写明：本周真的没有风险就忽略）
metrics-thin带量化数字的行数低于下限（默认 1，--min-metrics 可调）→ warn，指出不可检验与可检验的写法

用法

npx weekly-report-check report.md --json
npx weekly-report-check report.md --min-metrics 3

真实输入输出

输入
# 周报 2026-W46

这周很忙，做了很多事情，下周继续努力。
$ weekly-report-check weekly-sample.md
error done-missing 第0行 没有「本周完成」段或自标识行（认得：## 本周完成、已完成：…、已上线…）——报告没有事实底座
warn risks-missing 第0行 没有风险/阻塞段（认得：## 风险、阻塞：…、卡在…）——如果本周真的没有风险，忽略这条
warn metrics-thin 第0行 全文只有 0 行带量化数字（% 、个、条、次、人、天、小时…，下限 1）——「优化了性能」不可检验，「p95 从 820ms 降到 460ms」可以
fail: 0 done, 1 planned, 0 risks, 1 errors, 2 warnings

出口码：1。输出为真实 CLI 运行的逐字结果，由测试与工具保持同步。

出口码：0 干净、1 有发现、2 用法或读文件错误。--json 输出机器可读结果。DSH 内同样的函数在 POST /weekly-report-check/api（{"text":"…"} 或 {"path":"…"}），面板与 CI 调同一实现。

这是清单，不是专业人士。合同检查不是法律意见，发票检查不判税务合规，listing 检查不判商业价值。每条发现都是文本里可判定的结构缺陷，带行号。
只验结构，不验工作真伪：它验证汇报分开了完成与计划、点了风险、量化了至少一行；工作是否真的发生，看 demo 和 diff。段内 bullet 与自标识行不会重复计数，标题行永不算项。 · dsh-vertical-kit · 通用检查（哈希/引用/结构/表格/数字）在 dsh-verify-kit
