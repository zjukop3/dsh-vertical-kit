检查规则

规则判定
title-missing前几行里没有 `# 标题` → error
load-missing没有写清条件（并发、QPS、轮次、7-run、数据规模）→ error
latency-missing没有可比较的度量（分位、吞吐、median of N reps、best 0.65ms）→ error
env-missing没有环境（机器、CPU、线程数、平台、数据规模）→ error
baseline-missing没有基线对照（基线、优化前、191.2ms → 2.2ms、87×）→ warn（--strict 时 error）
conclusion-missing没有结论段（结论、Findings、Recommendation、结果分析）→ warn（--strict 时 error）
repro-missing没有复现方式（locust/k6/wrk、脚本路径、harness）→ warn（--strict 时 error）

用法

npx dsh-perf-report-check report.md --json
npx dsh-perf-report-check report.md --strict --warnings-fail

# 首页接口压测

error latency-missing 第0行 没有可比较的度量（认得：p50 340ms、p95、中位数 191ms、33 906 files/s、7-run medians）——单次跑出来的一个数字说明不了分布

出口码：1。输出为真实 CLI 运行的逐字结果，由测试与工具保持同步。

出口码：0 干净、1 有发现、2 用法或读文件错误。--json 输出机器可读结果。DSH 内同样的函数在 POST /perf-report-check/api（{"text":"…"} 或 {"path":"…"}），面板与 CI 调同一实现。

这是清单，不是专业人士。合同检查不是法律意见，发票检查不判税务合规，listing 检查不判商业价值。每条发现都是文本里可判定的结构缺陷，带行号。
