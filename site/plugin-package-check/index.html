检查规则

规则判定
manifest-missing目录里没有 package.json → error
manifest-unparsablepackage.json 不是合法 JSON → error
private标了 private，发不到 npm → error
bundle-missing没声明 dsh.bundle.patch，装不上 → error
patch-missing声明的 patch 文件不在 → error
patch-emptypatch 里没有任何 insert 行 → error
patch-name-mismatchpatch 挂的既不是自己也不是依赖 → error
files-omits-patchfiles 没把 patch 打进 tarball → warn
files-omits-detailfiles 没把 docs/DETAIL.md 打进去 → warn
engines-missing没有 engines.dsh → warn
bin-name-mismatchbin 里没有等于包名的键，npx <包名> 会 404 → warn
readme-missing / readme-install-missing没有 README，或里面没有 dsh plugin add → warn
locale-missing没有 locale/，插件页只剩包名 → warn
icon-missing没有图标，卡片是空白的 → warn

用法

npx dsh-plugin-package-check ./packages/my-plugin
npx dsh-plugin-package-check ./packages/my-plugin --json

真实输入输出

输入
null
$ plugin-package-check ./packages/dsh-adr-check
ok: dsh-adr-check 0 errors, 0 warnings

出口码：0。输出为真实 CLI 运行的逐字结果，由测试与工具保持同步。

出口码：0 干净、1 有发现、2 用法或读文件错误。--json 输出机器可读结果。DSH 内同样的函数在 POST /plugin-package-check/api（{"text":"…"} 或 {"path":"…"}），面板与 CI 调同一实现。

这是清单，不是专业人士。合同检查不是法律意见，发票检查不判税务合规，listing 检查不判商业价值。每条发现都是文本里可判定的结构缺陷，带行号。
校准语料是别人写的七个包加上本仓库自己的三十个。dsh-purge-community 的 bin 键里没有它自己的包名（所以 README 让人敲 npx dsh-purge-community 会 404），@claude-mem/dsh 是 private——这两条都是真的，不是规则挑刺。它不能判断插件好不好用，也看不见「tarball 里漏了目录里有的文件」这个反向问题（那要 npm pack --dry-run）。 · dsh-vertical-kit · 通用检查（哈希/引用/结构/表格/数字）在 dsh-verify-kit
