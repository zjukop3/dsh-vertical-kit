检查规则

规则判定
credit-code18 位统一社会信用代码字符集校验（数字 + A-HJ-NPQRTUWXY，排除 I/O/S/V/Z）→ error
invoice-number发票号码 20 位（数电票）或 8 位（纸质票）之外 → warn
amount-sum不含税 + 税额 ≠ 价税合计（超出容差）→ error，报三项的值
amount-partial勾稽三项缺一 → warn，点名缺哪个
amount-uppercase大写金额与价税合计不一致 → error
amount-ambiguous出现多个大写金额 → warn
buyer / seller没有购买方/销售方名称栏 → error

用法

npx dsh-invoice-check invoice.txt --json
npx dsh-invoice-check invoice.txt --tolerance 0.02

真实输入输出

输入
发票号码：24512000000123456789
统一社会信用代码：91330106MA27X8XXXX
购买方名称：甲科技有限公司
销售方名称：乙网络工作室

税额（小写）：¥679.25
价税合计（小写）：¥12,001.00
价税合计（大写）：壹万贰仟元整
$ invoice-check invoice-sample.txt
error amount-sum 第 5 行勾稽不平：不含税 11320.75 + 税额 679.25 = 12000，价税合计却是 12001（容差 0.02）
error amount-uppercase 大写金额 12000（第 8 行）与价税合计 12001（第 7 行）不一致
fail: 2 errors, 0 warnings

出口码：1。输出为真实 CLI 运行的逐字结果，由测试与工具保持同步。

出口码：0 干净、1 有发现、2 用法或读文件错误。--json 输出机器可读结果。DSH 内同样的函数在 POST /invoice-check/api（{"text":"…"} 或 {"path":"…"}），面板与 CI 调同一实现。

这是清单，不是专业人士。合同检查不是法律意见，发票检查不判税务合规，listing 检查不判商业价值。每条发现都是文本里可判定的结构缺陷，带行号。
勾稽是发票自己的算术，不是税务合规：税率是否适用、抬头是否对，都不在这五个判定里。 · dsh-vertical-kit · 通用检查（哈希/引用/结构/表格/数字）在 dsh-verify-kit
