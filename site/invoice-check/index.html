发票字段检查清单

它决定一件事：发票上能从文本判定的算术与格式是否成立。

dsh-agreement-checkdsh-invoice-checkdsh-listing-checkGitHub 源码npm

检查规则

规则判定
credit-code18 位统一社会信用代码字符集校验（数字 + A-HJ-NPQRTUWXY，排除 I/O/S/V/Z）→ error
invoice-number发票号码 20 位（数电票）或 8 位（纸质票）之外 → warn
amount-sum不含税 + 税额 ≠ 价税合计（超出容差）→ error，报三项的值
amount-partial勾稽三项缺一 → warn，点名缺哪个
amount-uppercase大写金额与价税合计不一致 → error
amount-ambiguous出现多个大写金额 → warn
buyer / seller没有购买方/销售方名称栏 → error

用法

npx invoice-check invoice.txt --json
npx invoice-check invoice.txt --tolerance 0.02

出口码：0 干净、1 有发现、2 用法或读文件错误。--json 输出机器可读结果。DSH 内同样的函数在 POST /invoice-check/api（{"text":"…"} 或 {"path":"…"}），面板与 CI 调同一实现。

这是清单，不是专业人士。合同检查不是法律意见，发票检查不判税务合规，listing 检查不判商业价值。每条发现都是文本里可判定的结构缺陷，带行号。
