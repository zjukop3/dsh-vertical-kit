DSH VERTICAL KIT

行业场景交付检查

Agent 已经产出结果、行业里的人准备接手的那一刻，这三个检查各自决定一件事：合同是否结构可审、发票算术是否成立、商品导出是否可上架。每个都是单个命令，从文件本身判定。

检查清单npm 包搜索名词它决定什么
合同结构检查清单dsh-agreement-check合同检查 / 合同审查清单这份合同在结构上是否可审
发票字段检查清单dsh-invoice-check发票检查 / 发票校验发票上能从文本判定的算术与格式是否成立
电商商品信息检查清单dsh-listing-check电商商品信息检查 / listing 检查商品导出表是否达到可上架的结构卫生
会议纪要检查清单dsh-meeting-notes-check会议纪要检查 / 会议记录检查这份纪要是否交代了谁在何时 carries 什么
简历检查清单dsh-resume-check简历检查 / 求职简历检查这份简历在书记层面是否可读、可达、时间自洽
发布说明检查清单dsh-release-notes-check发布说明检查 / 更新日志检查这份发布说明是否交代了哪个版本、何时、什么会坏、怎么迁移
周报检查清单dsh-weekly-report-check周报检查 / 工作汇报检查这份周报是否交代了做完了什么、接下来做什么、什么会卡住、进展是否可检验
缺陷报告检查清单dsh-bug-report-check缺陷报告检查 / bug 报告检查这份 bug 报告是否交代了在哪发生、怎么触发、差在哪
接口文档检查清单dsh-api-doc-check接口文档检查 / API 文档检查这份接口文档是否交代了怎么调、怎么证明身份、失败长什么样
测试报告检查清单dsh-test-report-check测试报告检查 / 用例统计检查这份测试报告的算术是否自洽、环境是否可复跑、失败是否有去处
提交信息检查清单dsh-commit-msg-check提交信息检查 / commit message 检查这条提交信息是否可被工具解析、在 log 里可读
Dockerfile 检查清单dsh-dockerfile-checkDockerfile 检查 / 镜像构建检查这个 Dockerfile 是否把可复现与最小权限写进了文件本身
环境变量示例检查清单dsh-env-example-check环境变量示例检查 / .env 检查这份示例文件是否只含占位符、键不重复、有用途说明
许可证检查清单dsh-license-check许可证检查 / LICENSE 检查这个 LICENSE 文件是否说了它看起来在说的那件事
事故复盘检查清单dsh-incident-report-check事故复盘检查 / 故障报告检查这份复盘是否给出了时间线、影响、根因与有人负责的后续

定位

护城河不在深度——专业产品随时碾压深度。在：离线可跑、出口码接 CI、免费、host 路由与 CLI 调同一函数。定位是「专业人士的前五分钟」，不是「专业人士的替代」。通用的五个检查（哈希/引用/结构/表格/数字）在 dsh-verify-kit。

在 DSH 中安装

八件作品都在同一个 format 1 索引源里，从 npm registry 解析，装完即用。在「插件」启用「自定义插件索引」，添加 https://zjukop3.github.io/dsh-review-outbox/plugins.json，按名字搜索安装（本仓库三件：agreement-check / invoice-check / listing-check）。
