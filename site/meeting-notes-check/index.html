检查规则

规则判定
date-missing全文没有任何日期（2026-11-16、11月16日、11/16、下周三）→ error
attendees-missing没有与会人/参会人/出席/Attendees 行或标题 → error
action-no-owner行动项没有负责人（负责人：…、@名字、X 负责）→ error，报行号
action-no-deadline行动项没有截止时间（11月20日前、2026-11-20、下周三）→ error，报行号
agenda-missing没有议程/议题标题或编号讨论点 → warn
decisions-missing没有决定/决议/结论 → warn（信息里写明：会议真的没有决定就忽略）
no-action-items没有任何行动项 → warn（同样带出口）

用法

npx meeting-notes-check notes.md --json
npx meeting-notes-check notes.md --no-require-agenda

# 项目周会

- [ ] 导出性能基线测试 负责人：李四

出口码：1。输出为真实 CLI 运行的逐字结果，由测试与工具保持同步。

出口码：0 干净、1 有发现、2 用法或读文件错误。--json 输出机器可读结果。DSH 内同样的函数在 POST /meeting-notes-check/api（{"text":"…"} 或 {"path":"…"}），面板与 CI 调同一实现。

这是清单，不是专业人士。合同检查不是法律意见，发票检查不判税务合规，listing 检查不判商业价值。每条发现都是文本里可判定的结构缺陷，带行号。
只验记录格式，不判断会议质量：它验证纪要写清了谁在何时 carries 什么，不能验证张三真的接了任务。编号行是整份纪要的组织方式，只有勾选框和行动标题下的编号项算任务。 · dsh-vertical-kit · 通用检查（哈希/引用/结构/表格/数字）在 dsh-verify-kit
