电商商品信息检查清单

它决定一件事：商品导出表是否达到可上架的结构卫生。

dsh-agreement-checkdsh-invoice-checkdsh-listing-checkGitHub 源码npm

检查规则

规则判定
title-short / title-long标题字符数越界（默认 10–60，可配）→ error，报行号与字数
title-stuffing同一关键词连写三遍或分隔出现三次以上 → warn，报词与次数
title-missing没有标题列或该行为空 → error
price-invalid价格不是 ≥ 0.01 的数字 → error
price-high价格超过上限（--max-price 配置）→ warn
sku-missing / sku-emptySKU 列缺失或为空 → error
sku-duplicateSKU 与更早的行重复 → error，报两行行号

用法

npx listing-check listings.csv --json
npx listing-check listings.csv --min-title 10 --max-title 60 --max-price 9999

出口码：0 干净、1 有发现、2 用法或读文件错误。--json 输出机器可读结果。DSH 内同样的函数在 POST /listing-check/api（{"text":"…"} 或 {"path":"…"}），面板与 CI 调同一实现。

这是清单，不是专业人士。合同检查不是法律意见，发票检查不判税务合规，listing 检查不判商业价值。每条发现都是文本里可判定的结构缺陷，带行号。
堆砌检测两种形态都认：连写（手机支架手机支架手机支架）和分隔重复；单字重复在中文标题里是常态，永不计入。认得的列名：标题 title/商品名称/名称，价格 price/售价，SKU sku/编码/货号。 · dsh-vertical-kit · 通用检查（哈希/引用/结构/表格/数字）在 dsh-verify-kit
