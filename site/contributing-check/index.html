检查规则

规则判定
title-missing没有 `# 标题`，也没有 RST 下划线标题 → error
setup-missing没有开发环境段，也没有 git clone / pnpm install 这类命令 → error
test-missing没有测试段，也没有可执行测试命令 → error
test-command-missing有测试段但里面没有一条能跑的命令 → error（「请确保测试通过」不是指令）
pr-missing没有提交 PR 的说明 → error
style-missing没有风格段，也没写「提交时自动格式化」→ warn（--strict 时 error）
questions-missing没有「到哪问」→ warn（--strict 时 error）
commit-missing没有提交信息约定（Conventional Commits / DCO）→ warn（--strict 时 error）
license-missing没有许可 / CLA / DCO 说明 → warn（--strict 时 error）
pointer-guide文档是「指路型」：自己没有命令，但点了明确目标 → warn，并报出目标

用法

npx contributing-check CONTRIBUTING.md --json
npx contributing-check CONTRIBUTING.md --strict --warnings-fail

真实输入输出

输入
# Contributing

Thanks for your interest. Please be nice.

$ contributing-check contributing-sample.md
error setup-missing 第0行 没有开发环境段（认得：## 开发环境、## Getting started、git clone / npm ci 这类命令）——新人卡在第一步就走了
error test-missing 第0行 没有测试段（认得：## 测试、## Running tests）——不知道该跑什么测试的人，交上来的 PR 是红的
error pr-missing 第0行 没有提交 PR 的说明（认得：## Pull request、## 贡献流程、## Submitting changes）——不知道你期待什么，第一次 PR 就会踩到你的隐性规矩
warn style-missing 第0行 没有代码风格段（认得：## 代码风格、## Lint，或明说提交时自动格式化）——风格要求藏在评审里，等于每次评审重讲一遍
warn questions-missing 第0行 没有「到哪问」的说明（认得：## 提问、Discord、mailing list、good first issue）——卡住的人只有放弃和硬猜两条路
warn commit-missing 第0行 没有提交信息约定（认得：Conventional Commits、Signed-off-by、DCO）——评审时才发现格式不对，返工的是对方
warn license-missing 第0行 没有许可/CLA/DCO 说明（认得：CLA、DCO、License）——贡献者不知道自己交出去的代码按什么授权
fail: 0 commands, 3 errors, 4 warnings

出口码：1。输出为真实 CLI 运行的逐字结果，由测试与工具保持同步。

出口码：0 干净、1 有发现、2 用法或读文件错误。--json 输出机器可读结果。DSH 内同样的函数在 POST /contributing-check/api（{"text":"…"} 或 {"path":"…"}），面板与 CI 调同一实现。

这是清单，不是专业人士。合同检查不是法律意见，发票检查不判税务合规，listing 检查不判商业价值。每条发现都是文本里可判定的结构缺陷，带行号。
