检查规则

规则判定
empty条目是空的 → error
yaml-shape列表、制表符、深于一层的嵌套 → error（明确不支持，不猜）；块标量与跨行引号标量是支持的
duplicate-key同一个键写两次 → error（YAML 静默取后一个）
unknown-keyurl/name/category/description/icon/tarball 之外的键 → error
missing-keyurl/name/category/description 缺项 → error
url-shape不是 https://github.com/<owner>/<repo>[/tree/<ref>/<path>]，或带结尾斜杠/.git/blob → error
name-shapename 与 url 指向同一个仓库 → error；只写包名（上游偶尔也收）→ warn
sub-path#sub 与 url 最后一段不一致 → warn（上游收过整条路径的写法）
category不在上游那 23 个取值里 → error
description-keys缺 en → error（唯一必填的语言）；缺 zh → warn（上游会补）
description-placeholder描述还是 TODO / lorem → error
description-thin描述短到读不出它做什么（en < 50 字符 / zh < 12 汉字）→ warn
description-parity中文那半明显短于英文（按汉字数比词数）→ warn
description-perioden 不以句号结尾 → warn（上游写法要求是一句话）
tarball-shapetarball 不是绝对 https 或不像 .tgz/.tar.gz → warn
icon-shape不是绝对 https 地址或不是图片扩展名 → warn
bundle-hint描述自己说「一次装一组」→ warn（上游第 7 条不收聚合包）
filename文件名与 url 推出的 owner__repo--path.yml 不一致 → warn
repo-package-missing给了 --repo 但那个（子包）目录或 package.json 不存在 → error
repo-bundle-missing那个包的 package.json 没有 dsh.bundle.patch → error（上游最常见的打回原因）
repo-patch-missingdsh.bundle.patch 指向的文件不存在 → error
repo-name-mismatch条目的 #sub 与包的 name 不一致 → warn

用法

npx dsh-plugin-entry-check data/plugins/owner__repo.yml
npx dsh-plugin-entry-check data/plugins/owner__repo.yml --repo ~/code/repo
npx dsh-plugin-entry-check - < entry.yml

真实输入输出

输入
$ plugin-entry-check bad-entry.yml
error empty 第0行 条目是空的——没有 url、name、category 的 yaml 交上去只会被拒
fail: 1 errors, 0 warnings

出口码：1。输出为真实 CLI 运行的逐字结果，由测试与工具保持同步。

出口码：0 干净、1 有发现、2 用法或读文件错误。--json 输出机器可读结果。DSH 内同样的函数在 POST /plugin-entry-check/api（{"text":"…"} 或 {"path":"…"}），面板与 CI 调同一实现。

这是清单，不是专业人士。合同检查不是法律意见，发票检查不判税务合规，listing 检查不判商业价值。每条发现都是文本里可判定的结构缺陷，带行号。
