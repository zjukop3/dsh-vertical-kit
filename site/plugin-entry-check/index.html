检查规则

规则判定
empty条目是空的 → error
yaml-shape列表、块标量、制表符、深于一层的嵌套 → error（明确不支持，不猜）
duplicate-key同一个键写两次 → error（YAML 静默取后一个）
unknown-keyurl/name/category/description/icon 之外的键 → error
missing-keyurl/name/category/description 缺项 → error
url-shape不是 https://github.com/<owner>/<repo>[/tree/<ref>/<path>]，或带结尾斜杠/.git/blob → error
name-shapename 必须是 owner/repo[#sub]，且与 url 指向同一个仓库 → error
sub-path#sub 必须等于 url 路径的最后一段，且两者互为前提 → error
category不在上游那 23 个取值里 → error
description-keysen 与 zh 缺一 → error
description-placeholder描述还是 TODO / lorem → error
description-thin描述短到说不清它做什么 → warn
description-parity中文那半明显短于英文（按汉字数比词数）→ warn
icon-shape不是绝对 https 地址或不是图片扩展名 → warn
bundle-hint描述自己说「一次装一组」→ warn（上游第 7 条不收聚合包）
filename文件名与 url 推出的 owner__repo--path.yml 不一致 → warn

用法

npx dsh-plugin-entry-check data/plugins/owner__repo.yml
npx dsh-plugin-entry-check - < entry.yml

真实输入输出

输入
url: 'https://github.com/owner/repo/tree/main/packages/my-plugin'
name: 'someone/else#my-plugin'
category: 'documents'
description:
  en: 'Checks things.'
  zh: '检查东西。'
icon: './icon.png'

$ plugin-entry-check bad-entry.yml
error name-shape 第0行 name 指向 someone/else，url 指向 owner/repo——评审会看这两个是不是同一个仓库
error category 第0行 category「documents」不在上游的 23 个取值里：agi ui usage theme model identity session memory tools wsl browser vision voice docs skill workflow git notify dev security remote market fun
error filename 第0行 文件名 bad-entry.yml 不符合 owner__repo.yml 或 owner__repo--path.yml
warn description-thin 第0行 description.en 只有 14 字符——一条说不清「它做什么」的条目，读者会跳过
warn description-thin 第0行 description.zh 只有 4 个汉字——中文读者读到的信息量太少
warn icon-shape 第0行 icon 用绝对 https 地址——相对路径在目录页里解析不了
fail: 3 errors, 3 warnings

出口码：1。输出为真实 CLI 运行的逐字结果，由测试与工具保持同步。

出口码：0 干净、1 有发现、2 用法或读文件错误。--json 输出机器可读结果。DSH 内同样的函数在 POST /plugin-entry-check/api（{"text":"…"} 或 {"path":"…"}），面板与 CI 调同一实现。

这是清单，不是专业人士。合同检查不是法律意见，发票检查不判税务合规，listing 检查不判商业价值。每条发现都是文本里可判定的结构缺陷，带行号。
语料是五份真实条目：四份已合并进 awesome-dsh-plugin，一份是我自己在评审中的 PR #18109。它们必须零发现——第一版在它们身上报出四种误报（嵌套 description 被读成缺失、#sub 拿整条路径去比、正文里合法的 <name> 被当成占位符、汉字数比英文字符数判译文像占位），四条同一个毛病：量的是我以为的写法。另有两处按上游正文纠正：分类是 23 个不是 24 个；#sub 写的是包目录名，不是路径。它读不到仓库，所以 dsh.bundle 声明、仓库年龄、代码是否真的有内容，仍由评审判定；第 7 条也只能给提示。 · dsh-vertical-kit · 通用检查（哈希/引用/结构/表格/数字）在 dsh-verify-kit
