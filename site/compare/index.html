DSH VERTICAL KIT · 17 CHECKS

全部 17 个检查一览

每个检查只做一件事：从一份文件本身判定一组可判定的缺陷，说出第几行、缺什么。它们不调用模型，不联网判定，CLI 与 host 路由调同一函数。用这张表选你要的那一个——选错了通常是名词对不上，而不是功能不够。

怎么选

先看你手上是什么文件：

  • 合同 → agreement-check；发票 → invoice-check；商品导出表 → listing-check
  • 会议纪要 → meeting-notes-check；简历 → resume-check；周报 → weekly-report-check
  • 发布说明 → release-notes-check；缺陷报告 → bug-report-check；接口文档 → api-doc-check
  • 测试报告 → test-report-check；提交信息 → commit-msg-check；PR 描述 → pr-description-check
  • Dockerfile → dockerfile-check；.env.example → env-example-check；LICENSE → license-check
  • 事故复盘 → incident-report-check；运维手册 → ops-runbook-check

通用缺陷（交付文件的哈希、报告引用、文档结构、Markdown 表格、数字写法）在 dsh-verify-kit，不在这个对照表里。

共同约束

  • 一条发现一行。每条都带行号；没有行号的建议没法动手改。
  • 只判可判定的。需要判断力的事不写成规则；需要判断力的事也不能假装判定了。
  • warn 与 error 分开。error 是「这份文件没说清一件事」，warn 是「说了但值得看一眼」，多数 warn 在信息里写明什么情况下可以忽略。
  • 出口码 0/1/2：干净、有发现、用法或读文件错误。可直接接 CI。
